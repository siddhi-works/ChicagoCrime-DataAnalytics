Understanding our dataset
from zero

What the data is · what every column means · data types · what was wrong · how we fixed it

Written in simple words. No coding knowledge needed.

1. What is a "dataset"? (start here)

Think of a dataset as one giant Excel sheet.

  • Each row is one thing. Here, one row = one crime report written by the Chicago police.
  • Each column is one fact about that thing: when it happened, what type of crime, whether someone was arrested, and so on.
Example of one row, in words: "Report number 13311263 · happened on a Friday at 3:39 AM · type: a theft-like category · place: a residence · an arrest was made · police district 10 · year 2022."

2. Our dataset at a glance

QuestionAnswer
What is it?Police crime reports from Chicago, USA
Where did we get it?Given to us by the TECHVERSE organisers as an Excel file called Crime Dataset.xlsx (about 150 MB). It looks like the City of Chicago's public "Crimes – 2001 to Present" data, but we could not confirm that, so we say "appears to be".
How many rows?1,048,575 (about one million crime reports)
How many columns?22 in the original file. After our work: 33 (we added helper columns and removed a few).
What years?2001 to 2026 (up to 26 Sep 2026)
Is it complete?No. It has exactly Excel's row limit, so it is a slice of a bigger table. Only two periods are well filled: Apr 2015–Jul 2017 and Oct 2025–Aug 2026. Other years have only a few hundred reports a month.
Did we change the original?No. We only read it. A digital fingerprint (SHA-256) proves it is unchanged.

6. Preprocessing: step by step in simple words

Preprocessing means getting the data ready before analysis, like washing and chopping vegetables before cooking. Our golden rule: change as little as possible, write down every change, delete nothing.

Step 1: Load the file safely

  • What was wrong: the Excel file is huge (150 MB) and some columns mix numbers and text.
  • What we did: opened it in read-only mode (so it cannot be changed), turned mixed columns into plain text, and saved a fast copy for later use.
  • Proof it was untouched: a fingerprint (SHA-256) taken at the start matches the one at the end.

Step 2: Fix the dates (the biggest problem)

  • What was wrong: Excel thought some dates were written day/month instead of month/day. So "03/01/2023" (March 1st) was read as "3 January". This only happened when the day was 12 or lower, because a day like 29 cannot be a month.
  • How we found it: 623,937 date cells were plain text with days always 13 or more (always correct). 424,638 cells were real Excel dates with days always 12 or less (the swapped ones).
  • What we did: for those 424,638 cells we swapped the month and day back.
  • Simple before → after: 2023-03-01 (wrong) → 2023-01-03 (correct).
  • How we know it worked:
    • The year still equals the Year column in 100% of rows.
    • Records "updated before they happened" dropped from 3.3% to 0%.
    • The monthly crime chart matches the competition handout exactly (28 months, lowest 18,710 in Feb 2016).

Step 3: Tidy the text

  • What was wrong: extra spaces and inconsistent capitals could make "Theft" and "THEFT " look like two different categories.
  • What we did: removed spaces at the ends and made text upper case in Primary Type, Description, Location Description and Block.

Step 4: Merge two labels for one offence

  • What was wrong: CRIM SEXUAL ASSAULT and CRIMINAL SEXUAL ASSAULT are the same offence under two names (a renaming).
  • What we did: kept the original column untouched (the handout counts 33 types and lists both names as violent) and added a second column with them merged (32 types) for deeper analysis.

Step 5: Handle map positions

  • Missing positions: 327,690 rows (31.3%) have no latitude or longitude. We did not guess them. We flagged them with has_coords and draw maps only from rows that have a position.
  • Impossible positions: 16 points were outside Chicago (for example, in another state). We set them to missing.
  • Area codes: a community area of 0 does not exist, so 2,616 zeros became missing.

Step 6: Check for duplicates

  • Duplicate IDs: 0. Fully repeated rows: 0.
  • 13 repeated case numbers were kept because they have different IDs (real separate reports).

Step 7: Spot suspicious values, but do not delete them

  • "Time unknown" stamps: 5.5% of reports are stamped exactly 00:00 or 12:00, far more than a real clock would give. We flagged them (default_time). The handout's night-time KPI keeps them (17.7%); we also show the number without them (15.8%).
  • Too many on the 1st of the month: some crime types have far too many reports dated the 1st (sex offences: 14.4% instead of about 3.3%). This probably means the true date was unknown. We flag it as a likely explanation, not a proven fact.

Step 8: Add helper columns

We created the 13 columns in section 5 (hour, weekday, season, time of day, crime category, and so on) using the handout's exact definitions.

Step 9: Test whether the missing data is random

  • In Apr 2015–Jul 2017 only 1.7% lack positions, but they are mostly sensitive crime types (sex offence 13.9%, offences involving children 12.6%), probably for privacy.
  • In Oct 2025–Aug 2026, 99.96% lack positions, so the map uses only the first period.

Step 10: Save and log everything

The cleaned table is saved, and every change with its count is written to cleaning_log.json, so anyone can see exactly what was done.

7. Missing data: what it is and what we chose

Missing data = an empty cell: the value is unknown. It is not zero, and it is not an error we can quietly fix.

Three common options:

OptionWhat it meansRiskDid we use it?
Delete the rowsRemove rows with gapsChanges the totals (the handout needs exactly 1,048,575)No
Fill in (impute)Guess a value (average, nearest place…)Invents data; the rulebook forbids fabricating dataNo (except the word "UNKNOWN" for place)
Leave it and flag itKeep the gap, count it, and use only rows that have the valueFewer rows for that one analysisYes
ColumnMissingOur treatment
Latitude, Longitude, X, Y327,690 (31.3%)Left empty + flag has_coords; maps use only rows with positions
Community Area16,505 + 2,616 zeros = 19,121Left empty (zeros turned into empty)
Ward16,478Left empty
Location Description8,337Filled with "UNKNOWN" (honest label, keeps the row countable)
Everything else0Nothing needed
In one sentence: we never guess, never delete; we either label it UNKNOWN, leave it empty, or flag it, and every chart that depends on it says so.

8. How to double-check a column yourself (examples)

  • Count rows: total rows = 1,048,575 → this is KPI K1.
  • Count True values: Arrest = True appears 214,846 times → ÷ 1,048,575 = 20.49% arrest rate.
  • Count different values: Primary Type has 33 different values → KPI K4.
  • Count empties: Ward has 16,478 empty cells.
